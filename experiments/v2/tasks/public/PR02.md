## Objective

Add the ability to cancel an existing order.

## User-visible behaviour

A `POST /orders/{id}/cancel` request marks the order as cancelled and returns the
updated order. Sending the request again returns the same cancelled order, which is
how a caller observes that the change was kept.

## Inputs and outputs

- Input: the order identifier from the URL path. No request body is required, and
  any request body is ignored.
- Success output: HTTP 200 with the updated order as a JSON body, using the same
  keys as a single order response: `id`, `customerId`, `items`, `total`, `status`
  and `createdAt`, where each element of `items` has `productId`, `name`,
  `quantity`, `unitPrice` and `subtotal`, and where `status` is exactly
  `cancelled`.

## Error behaviour

Every failure responds with the service's existing error JSON body — the keys
`error` and `message` (both non-empty strings) alongside the `correlationId` key it
already returns:

- No order exists for the identifier: HTTP 404 with `error` exactly
  `NotFoundError`.
- The order's current status is `shipped` or `delivered`, so it can no longer be
  cancelled: HTTP 409 with `error` exactly `ConflictError`.

`message` is free text and only has to be non-empty.

## Constraints

- Cancelling an order whose status is already `cancelled` is not an error: respond
  with HTTP 200 and the cancelled order, exactly as the first cancellation did.
- After a successful cancellation, sending the same request again returns the same
  cancelled order.
- Only the requested order changes; other stored orders are unaffected.
- Existing endpoints keep their current behaviour and responses unchanged.

## Functional completion criteria

- Cancelling an order whose current status is `pending`, `confirmed` or
  `cancelled` returns HTTP 200 with `status` exactly `cancelled`, and repeating the
  request returns the same cancelled order.
- Cancelling an order whose current status is `shipped` or `delivered` returns HTTP
  409 with `error` exactly `ConflictError`.
- Cancelling a non-existent order returns HTTP 404 with `error` exactly
  `NotFoundError`.
