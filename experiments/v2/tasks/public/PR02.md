## Objective

Add the ability to cancel an existing order.

## User-visible behaviour

A `POST /orders/{id}/cancel` request marks the order as cancelled and returns the
updated order. A later fetch of that order shows the cancelled status.

## Inputs and outputs

- Input: the order identifier from the URL path.
- Success output: HTTP 200 with the updated (cancelled) order as a JSON body.

## Error behaviour

- If no order exists for the identifier, respond with HTTP 404 and the standard
  error body.
- An order that has shipped or been delivered cannot be cancelled: respond with
  HTTP 400 and the standard error body.
- Cancelling an already-cancelled order returns the cancelled order (idempotent)
  with HTTP 200.

## Constraints

- After a successful cancellation, reading the order back shows the cancelled
  status.
- Only the requested order changes.

## Functional completion criteria

- Cancelling a still-cancellable order succeeds and is visible on a later read.
- Cancelling a shipped or delivered order returns HTTP 400.
- Cancelling a non-existent order returns HTTP 404.
