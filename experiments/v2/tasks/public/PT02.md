## Objective

Add the ability to list the orders that belong to a given customer.

## User-visible behaviour

A `GET /orders?customerId={customerId}` request returns every stored order whose
customer identifier matches `{customerId}`, together with a count of how many
orders were returned. Each order in the result uses the same fields as a single
order response.

## Inputs and outputs

- Input: the customer identifier, supplied as the `customerId` query parameter.
- Success output: HTTP 200 with a JSON body containing the customer identifier,
  the array of matching orders, and the number of orders returned.

## Error behaviour

- If the `customerId` query parameter is missing or empty, respond with HTTP 400
  and the service's standard error JSON body.
- A customer with no orders is not an error: return HTTP 200 with an empty array
  and a count of zero.

## Constraints

- The result must contain only the orders for the requested customer; orders
  belonging to other customers must never appear.
- The reported count must equal the number of orders in the returned array.

## Functional completion criteria

- Creating several orders for one customer and one for another, then listing the
  first customer, returns exactly the first customer's orders and the correct
  count.
- Listing a customer with no orders returns an empty array and a count of zero.
- Listing with no `customerId` returns HTTP 400 with the standard error body.

## Validation

Run `npm run ci:agent`; it must pass.
