## Objective

Add the ability to list the orders that belong to a given customer.

## User-visible behaviour

A `GET /orders?customerId={customerId}` request returns every stored order whose
customer identifier matches `{customerId}`, together with a count of how many
orders were returned.

## Inputs and outputs

- Input: the customer identifier, supplied as the `customerId` query parameter.
- Success output: HTTP 200 with exactly this JSON body:

```json
{
  "customerId": "<the requested customer identifier>",
  "orders": [],
  "count": 0
}
```

- `customerId` equals the identifier supplied in the query string.
- `orders` is an array whose elements each use the same keys as a single order
  response: `id`, `customerId`, `items`, `total`, `status` and `createdAt`, where
  each element of `items` has `productId`, `name`, `quantity`, `unitPrice` and
  `subtotal`.
- `count` is a JSON number and always equals the number of elements in `orders`.
- The position of an order inside `orders` is not part of the required behaviour.
  The array may be returned in any order; correctness is judged on which orders
  are present, never on where they appear in the array.

## Error behaviour

- If the `customerId` query parameter is missing or is an empty string, respond
  with HTTP 400 and the service's existing error JSON body, with `error` exactly
  `ValidationError`, a non-empty `message`, and the `correlationId` key it
  already returns.
- A customer with no orders is not an error. Respond with HTTP 200 and:

```json
{
  "customerId": "<the requested customer identifier>",
  "orders": [],
  "count": 0
}
```

## Constraints

- `orders` must contain only the orders for the requested customer; orders
  belonging to other customers must never appear.
- `count` must equal the number of elements in `orders`.
- Existing endpoints keep their current behaviour and responses unchanged.

## Functional completion criteria

- Creating several orders for one customer and one order for another customer,
  then listing the first customer, returns exactly the first customer's orders
  (in any array order) and a `count` equal to how many were returned.
- Listing a customer with no orders returns `orders` as `[]` and `count` as `0`.
- Listing without a `customerId` returns HTTP 400 with `error` exactly
  `ValidationError` and a non-empty `message`.

## Validation

Run `npm run ci:agent`; it must pass.
