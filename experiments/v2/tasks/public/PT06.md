## Objective

Not-found responses are handled inconsistently across order endpoints. Make them
consistent, reusing the service's existing standard error response.

## User-visible behaviour

- Any request that targets an order that does not exist returns HTTP 404 with the
  service's standard error JSON body: an error name, a human-readable message,
  and the request's correlation identifier.
- The correlation identifier in the error body matches the request's correlation
  identifier (generating one if the request did not supply it).
- Validation failures continue to return HTTP 400 with that same standard error
  body shape.

## Inputs and outputs

- No new endpoints or request fields.
- The observable effect is a single, consistent error body shape for not-found
  and validation failures across order endpoints.

## Constraints

- All order endpoints use the same error body shape; do not introduce a second,
  differently-named error body for not-found.
- Successful responses and their status codes are unchanged.

## Functional completion criteria

- Requesting a non-existent order on each affected endpoint returns HTTP 404 with
  the standard error body including the matching correlation identifier.
- A validation failure still returns HTTP 400 with the same error body shape.
- The error body shape is identical across the endpoints.

## Validation

Run `npm run ci:agent`; it must pass.
