## Objective

Add the ability to change the status of an existing order.

## User-visible behaviour

A `PATCH /orders/{id}/status` request changes that order's status and returns the
updated order. Sending the same request again returns the order with that same
stored status, which is how a caller observes that the change was kept.

## Inputs and outputs

- Input: the order identifier from the URL path, and a JSON request body of
  exactly:

```json
{
  "status": "shipped"
}
```

  The accepted `status` values are exactly `pending`, `confirmed`, `shipped`,
  `delivered` and `cancelled`.

- Success output: HTTP 200 with the updated order as a JSON body, using the same
  keys as a single order response: `id`, `customerId`, `items`, `total`, `status`
  and `createdAt`, where each element of `items` has `productId`, `name`,
  `quantity`, `unitPrice` and `subtotal`, and where `status` is the requested
  value.

## Error behaviour

Every failure responds with the service's existing error JSON body — the keys
`error` and `message` (both non-empty strings) alongside the `correlationId` key
it already returns:

- No order exists for the identifier: HTTP 404 with `error` exactly
  `NotFoundError`.
- The request body has no `status` key: HTTP 400 with `error` exactly
  `ValidationError`.
- `status` is an empty string: HTTP 400 with `error` exactly `ValidationError`.
- `status` is not one of the five accepted values: HTTP 400 with `error` exactly
  `ValidationError`.
- The order's current status is `delivered` or `cancelled`, so it can no longer
  change: HTTP 409 with `error` exactly `ConflictError`.

`message` is free text and only has to be non-empty.

## Constraints

- After a successful change, sending the same request again returns the order
  with that same status.
- Any change from a current status other than `delivered` or `cancelled` to any
  one of the five accepted values is allowed, including a change to the status the
  order already has.
- Only the requested order changes; other stored orders are unaffected.
- Existing endpoints keep their current behaviour and responses unchanged.

## Functional completion criteria

- Changing the status of an existing order whose current status is not
  `delivered` or `cancelled` returns HTTP 200 with the updated order, and
  repeating the same request returns the same stored status.
- Changing an order whose current status is `delivered` or `cancelled` returns
  HTTP 409 with `error` exactly `ConflictError`.
- A request body without `status`, with an empty `status`, or with a `status`
  outside the five accepted values returns HTTP 400 with `error` exactly
  `ValidationError`.
- Changing a non-existent order returns HTTP 404 with `error` exactly
  `NotFoundError`.

## Validation

Run `npm run ci:agent`; it must pass.
