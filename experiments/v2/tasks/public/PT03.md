## Objective

Add the ability to change the status of an existing order.

## User-visible behaviour

A `PATCH /orders/{id}/status` request with a target status in its JSON body
changes that order's status and returns the updated order. A subsequent fetch of
the same order reflects the new status.

## Inputs and outputs

- Input: the order identifier from the URL path and a target status in the JSON
  request body.
- Success output: HTTP 200 with the updated order as a JSON body.

## Error behaviour

- If no order exists for the identifier, respond with HTTP 404 and the standard
  error body.
- An order that has already been delivered or cancelled can no longer change
  status: respond with HTTP 400 and the standard error body.
- An unknown or empty target status value: respond with HTTP 400 and the standard
  error body.

## Constraints

- After a successful change, reading the order back returns the new status.
- Only the requested order changes; other stored orders are unaffected.

## Functional completion criteria

- Changing the status of an existing, still-changeable order succeeds and is
  visible on a later read.
- Changing an order that is delivered or cancelled returns HTTP 400.
- Changing a non-existent order returns HTTP 404.

## Validation

Run `npm run ci:agent`; it must pass.
